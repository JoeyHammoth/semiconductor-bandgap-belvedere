# Accessibility

Target: **WCAG 2.2 AA**. Accessibility is an acceptance criterion, not a polish task; scenes are not allowed to be the only way to reach a result.

## 1. Principles applied to this project

- **Every visual has a non-visual equivalent.** Each scene ships an adjacent table and a generated one-sentence summary. The evidence ledger *is* the accessible form of the comparison.
- **Every motion has a static alternative.** Under `prefers-reduced-motion: reduce`, animations collapse and scenes render their end state.
- **Colour is never the only encoding.** Stiff/sloppy displacement, model identity and uncertainty all carry a redundant shape, label or pattern.
- **The accent colour is checked, not assumed.** Accent is derived from the selected diode's emission colour. `scripts/contrast.mjs` parses the token palette in both themes and fails CI below 4.5:1; if a future accent fails, the runtime must clamp its OKLCH lightness (or fall back to the theme's default accent) until the ratio passes. The check reads `tokens.css`, so the CSS cannot drift from the gate.

## 2. Requirements

| Area | Requirement |
|---|---|
| Keyboard | all controls reachable and operable; visible focus ring at ≥ 2 px with 3:1 contrast |
| Touch | targets ≥ 44 × 44 px |
| Layout | usable from 360 px wide; no horizontal scrolling at 320 px |
| Text | body ≥ 16 px; zoom to 200% without loss of content |
| Semantics | landmarks, heading order, labelled controls; no `div` buttons |
| Live regions | sampler/evidence progress announced politely; results announced on completion |
| Canvas/SVG | `role="img"` with descriptive label plus the adjacent data table |
| Heavy scenes | opt-in on small or low-power devices ("Play interactive scene"), never autoplay |
| Timing | no time limits; tour mode is pausable and skippable |
| Flashing | no content flashing more than three times per second |

## 3. Testing

- `axe-core` via Playwright on every route, in CI, failing on serious or critical violations.
- Playwright runs in Chromium, Firefox and WebKit, so the WebGPU → WebGL2 → static chain is exercised on engines with different support.
- Lighthouse CI accessibility category with an enforced threshold.
- `node scripts/contrast.mjs` checks body text and accent links in both themes at 4.5:1.
- Manual keyboard pass per scene before it is marked done.
- Reduced-motion pass: every scene must render a meaningful static state.
- Screen-reader spot check on the landing page, infer view and ledger before a release. **Phase 1 waiver (2026-11-24):** this manual spot check is explicitly waived by the project owner for the Phase 1 release; automated axe-core coverage on the landing page and `/infer/` in CI is the acceptance evidence. No manual screen-reader pass is claimed, and the keyboard requirements are not waived.

## 4. Known risks

- Dense posterior clouds on Canvas are not individually accessible; the table and summary carry the information instead.
- WebGPU scenes may be unavailable; the fallback chain in [`architecture.md`](architecture.md) is part of the accessibility story, not just performance.
- The status bar updates frequently by design; it is `aria-live="off"` for continuous values and announces only state changes.
