# Support

This is a personal project maintained on a best-effort basis. There is no paid support, no service-level agreement, and no guarantee that a request will be implemented.

## Where to go

| You need | Where |
|---|---|
| A bug in the site, a wrong number or a broken build | [Bug report](https://github.com/JoeyHammoth/semiconductor-bandgap-belvedere/issues/new?template=bug_report.yml) |
| A capability, scene or algorithm | [Feature request](https://github.com/JoeyHammoth/semiconductor-bandgap-belvedere/issues/new?template=feature_request.yml) |
| A primary-source check or a physics question | [Research task](https://github.com/JoeyHammoth/semiconductor-bandgap-belvedere/issues/new?template=research_task.yml) |
| Help setting up, running a check or reading a result | [Open a question](https://github.com/JoeyHammoth/semiconductor-bandgap-belvedere/issues/new?labels=question) |
| A security or privacy problem | [SECURITY.md](SECURITY.md): private advisory, never a public issue |
| How to build, test or open a PR | [CONTRIBUTING.md](CONTRIBUTING.md) |

## Before opening an issue

- Search the open and closed issues; triage labels and closed reasons are kept visible.
- Include the commit hash from the site's receipts footer, your browser, and the model or dataset you selected.
- For a wrong number, name the claim and the row in [`docs/validation.md`](docs/validation.md) it belongs to. A number that disagrees with that table is a bug; a number the table marks **unavailable** is a known limit, not a bug.

## What to expect

Triage happens in batches, so replies are best-effort rather than guaranteed. Issues that need the maintainer's judgment (physics, validation tolerances, licensing) may wait longer; they carry a label that says so rather than sitting silent.
